# Vancouver Transit Dashboard

Live TransLink departures, delays and vehicle positions for Metro Vancouver.

- `frontend/`: Vite + React + TypeScript app
- `backend/`: FastAPI service that reads TransLink's GTFS-Realtime feeds
- `backend/data/`: GTFS static lookups (stops, routes, trips, shapes) generated by
  `backend/scripts/build_static_data.py`

## Running locally

Backend (needs a [TransLink API key](https://www.translink.ca/about-us/doing-business-with-translink/app-developer-resources)):

```bash
cp backend/.env.example backend/.env   # then add your TRANSLINK_API_KEY
python -m venv backend/venv
backend/venv/bin/pip install -r backend/requirements.txt
backend/venv/bin/uvicorn backend.main:app --port 8000 --reload
```

Frontend:

```bash
cd frontend
npm install
npm run dev
```

In development the frontend calls `http://localhost:8000`. Set `VITE_API_URL`
(see `frontend/.env.example`) to point it somewhere else.

## Deploying to Vercel

The frontend and backend deploy together as one Vercel project using Vercel
Services. The site is served at `/`, and `/api/*` is routed to FastAPI with the
`/api` prefix stripped.

1. Import the GitHub repo in Vercel. The root `vercel.json` configures both
   services, so leave the project's Root Directory at the repo root. Every push
   to `main` deploys.
2. In the project's Settings → Environment Variables, set `TRANSLINK_API_KEY`.

### Refreshing the static data

TransLink publishes new GTFS static data weekly. `backend/data/` is committed
because Vercel cannot build it at startup, so refresh it by hand and push:

```bash
backend/venv/bin/python backend/scripts/build_static_data.py
git add backend/data
git commit -m "chore: refresh GTFS static data"
```

The backend logs a warning at startup when the data is more than a week old.
